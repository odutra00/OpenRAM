Durante o uso do OpenRAM, detectei que os roteamentos geram muitos erros de DRC.
Eu utilizei como base o projeto freePDK45. Memso colocando as regras de DRC da
tecnologia utilizada (TSMC65N) no tech.py, nao consegui fazer parar a geração
de erros de DRC de espaçamento, edges, etc.
Resolvi então partir para outra abordagem.
O OpenRAM gera uma netlist SPICE extremamente hierarquizada, o que torna fácil sua
conversão para verilog estrtutural., tornando possível o roteamento no Innovus.
Assim, mantive os arrays de componentes analógicos que ele cria, fazendo o override
das classes:

As 5 primeiras apenas dizem ao OpenRAM para usar minhas c-elulas digitais full 
custom, além do precharge pois o padrao no freepdk45 é crias os gds dessas células 
pelo python parametrizado.
As demais já são os arrays das células analógicas necessárias para o acionamento
da SRAM. Então modifiquei essas células em technology/tsmc65/custom para que o 
OpenRAM não posicionasse vias, que é o grande gerador de erros de DRC.
A ligação das celulas internas de cada vetor é feita por Abutsmen e roteamentos de
curto circuito de vdd e gnd são feitos por trilhas que interconectam vias previamente
posicionadas no layout de cada celula.
Assim, lembre-se:
- O override das celulas python que desenha 
alguns dos blocos parte do princípio que o layout foi feito daquele jeito.
O override das celulas python é feito na pasta 
$OPENRAM_HOME/../technology/$SUA_TECNOLOGIA/custom
Utilize o projeto da tecnologia tsmc65N como referencia.

Par a a transofrmação do SPICE em Verilog estrutural, criei um script python 
technology/tsmc65N/spice_to_structural_verilog.py
Leia as instruções de como usá-lo no proprio arquivo.
Basciamente ele aceita como argumento uma netlist spice. Dentro dele deve ser configurado
as instancias que devem ser descartadas (serão feitas pelo Innovus) e instâncias
que devem sair de dentro de uma instancia maior e ir pro topo, de forma que o Innovus
faça o roteamento.

=================== Y = 0.10 µm =================================== BORDA DO prBoundary
                    |  Trilha GND (Metal 1)             |

Os nomes dos pinos devem ser iguais aos relatados nas células do freepdk45, incluindo a camada de metal.
A geometria do pino deve ser obrigatoriamente retangular. No caso de células com rails de vdd e gnd (dff, inv, nand2, etc, o rail deve ser retangular (verifique se não há um stub no referido metal. Se houver, faça um retangulo do metal em questão pegando o rail inteiro, caso contrário haverá problemas de roteamento dos pinos de alimentação.
Tanto o label do pino, quanto a geometria que o contém, devem ser obrigatoriamente do Metal em questão, mas tem que ser drawing. Não pode ser pino.  Isso atrapalha porque para o lvs funcionar no virtuoso pelo PVS, pinos tem que ser do tipo pin já que no esquemático a gente coloca pinos também.



########################## Arquivos SPICE #########################
CIW e Virtuoso não geram a netlist SPICE do circuito. Se vc mandar exportar, tem a opçção CDL que vem com muitos parâmetros que podem dar problema no parser do OpenRAM. Limpe-os de forma a ficarem iguais aos da pasta sp_lib do freepdk45. Lembre-se também de colocar os pinos na mesma ordem dos arquivos do freepdk45 (olhe as netslists aspice do freepdk45 em technology/freepdk45/sp_lib.
Melhor do que esportar em CDL é pegar a netlist gerada no LVS.

############################ Arquivos GDS ########################
Para exportacao pelo virtuoso acesse a aba More Options e:
--> flatten Pcells, incluindo vias e pcells. 
--> Do not Preserve Pcell Pins
--> Flatten Vias
--> Output paths as polygons
--> Merge connected path segs

Isso garantirá que haja apenas uma prBoundary na célula exportada (obrigatório para o  OpenRAM) e que sejam gerados edges nos roteamentos.

    def write_macros(self, output_path=None):
        """Write selected SRAM blocks as independent GDS and LEF macros."""

        if OPTS.netlist_only:
            return

        if output_path is None:
            output_path = OPTS.output_path

        os.makedirs(output_path, exist_ok=True)

        macro_names = [
            "precharge_array",
            "write_driver_array",
            "sense_amp_array",
            "capped_replica_bitcell_array",
        ]

        def find_macros(design):
            found = {}

            for inst in design.insts:
                # A própria instância é um dos macros desejados
                for macro_name in macro_names:
                    if inst.mod.name.endswith(macro_name):
                        found[macro_name] = inst.mod

                # Procura também dentro da hierarquia
                found.update(find_macros(inst.mod))

            return found

        macros = find_macros(self.s)

        for macro_name in macro_names:
            if macro_name not in macros:
                debug.warning("Macro {0} not found.".format(macro_name))
                continue

            macro = macros[macro_name]

            gdsname = os.path.join(output_path, macro.name + ".gds")
            lefname = os.path.join(output_path, macro.name + ".lef")

            debug.print_raw("GDS: Writing macro {0} -> {1}".format(
                macro.name, gdsname))
            macro.gds_write(gdsname)

            debug.print_raw("LEF: Writing macro {0} -> {1}".format(
                macro.name, lefname))
            macro.lef_write(lefname)
